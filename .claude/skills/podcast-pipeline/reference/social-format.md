# 社交媒体文案格式规则

> Step 4 生成文案时的格式约束。

## 文案格式

- 正文 + 签名 + tags **总计 ≤ 1000 字符**（小红书 desc 字段硬限制）
- 发送函数拼接后自动校验总量；正文写到 **850-900 字符** 即可，签名和 tags 约占 100 字符
- Tags 必含 `#gegewu #嗝嗝巫 #gegeewu播客日记`，总数 ≤9 个
- 写入 `output/<podcast>/social.txt` 和 `tags.txt`

### ⚠️ 段落格式硬约束（每次执行必须严格遵循，无论是第几集）

```
第一段正文（概括性引入）
                          ← 必须有一个空行
第二段正文（展开论述）
                          ← 必须有一个空行
第三段正文（关键细节）
                          ← 必须有一个空行
第四段正文（收尾/前瞻）
```

- **段落之间必须且只能用一个空行（`\n\n`）分隔**，不得多也不得少
- **段落内部不换行**，一段就是连续的一行文字
- 不要用 `\n` 单换行分隔段落 — 那不是段落分隔，是同一段内的换行
- 正文 3-5 段，每段 150-250 字符
- 签名 `by gegeewu 🦉` 不写入 social.txt（发送时自动追加）
- **⛔ 禁止 markdown 语法**：social.txt 是纯文本文件，禁止写入 `---`、`**`、`#`（tag 除外）、`>`、`*`、`_` 等任何 markdown 标记；文件末尾不得有多余空行或符号残留

## Telegram 发送格式（由 `send_cards_and_text()` 自动执行，共三步）

```
消息1（标题文字）：
{中文标题} - {podcast_name} 播客
> YouTube 来源不加"播客"后缀：{中文标题} - {podcast_name}

消息2-N（卡片图片）：
podcast_card_01.png, podcast_card_02.png, ...（逐张发送）

消息N+1（正文+tags 合并发送）：
（正文，段落间空行分隔）

by gegeewu 🦉

#tag1 #tag2 ...
```

> 注：`by gegeewu 🦉` 签名由 `send_cards_and_text()` 自动追加，social.txt 不需要手动写入签名。

## 标题规则

- 准确传达内容核心，用自然中文表达，像中文母语者会怎么起标题
- 避免过度文艺/抽象，读者要能一眼看出讲什么
- **嘉宾访谈类**（有明确知名嘉宾）：标题必须包含嘉宾姓名或其核心身份标签，让读者一眼知道是谁
  - 例：Lex x Jensen Huang → ✅「黄仁勋谈AI工厂」❌「AI中盘时代」（读者不知道是谁说的）
  - 例：Sam Altman 访谈 → ✅「Sam Altman：下一步是什么」❌「AI下半场」
- **主题讨论类**（无特定知名嘉宾）：标题聚焦核心观点/话题即可
  - 例：Composio CTO 访谈 → ✅「AI Agent 工具层怎么做」（CTO 非公众知名人物，不必写姓名）
- 例："Agent Inference at Planetary Scale" → 「当推理遇上数据中心级调度」（而非「行星级代理推理」）
- 反例："What the New ChatGPT 5.4 Means for the World" → ❌「5.4的裂缝」✅「GPT-5.4 强在哪弱在哪」
- 控制在 12 字以内（含嘉宾姓名时可放宽至 14 字），超出则提炼重写
- 不加《》符号
